# 验收、反模式与交付清单

把这份文件当作"审查现有界面是否符合 Linear Style"工作流的核心检查表。遇到具体颜色/字体/组件数值问题时，交叉查阅 `color.md`、`typography.md`、`layout.md`、`components.md`。

## 不像 Linear，通常不是少了紫光

| 反模式 | 问题 | 应替换为 |
|---|---|---|
| 满屏紫色标题、渐变按钮、彩色边框 | 没有注意力层级 | 中性主体 + 一个操作重心 |
| 所有信息都包卡片 | 结构碎片化 | 行、分组、对齐与必要面板 |
| 所有卡片 24px 圆角、大投影 | 组件职责不分 | 按角色用 8/12px，普通面板无投影 |
| 12px 低对比说明看似精致 | 读不清、不可用 | 合规 muted + 合适字号 |
| 每个标题 800 bold | 层级只剩喊叫 | 字号、位置、适度 500/600 与间距 |
| 因 510 是"签名字重"就强行应用到所有语言 | 忽略字体与平台 | 映射到实际可用字重并实测 |
| 一屏只能一处有色 | 焦点/状态被隐藏 | 品牌收敛，必要状态仍完整 |
| 每段滚动入场、每卡 hover 位移 | 高频干扰 | 快速局部反馈、少量有目的动效 |
| 任何异步都乐观"成功" | 数据与权限风险 | 按风险选择确认、pending、回滚 |
| 所有表格变手机卡片 | 丢失比较关系 | 摘要视图或局部可滚动表格 |
| 强制 Cmd+K、快捷键、动态主题全家桶 | 为风格增加功能 | 只有任务确有需求才增加 |
| 套用未经版本验证的框架配置 | 表面跨架构，实际不可运行 | 稳定语义契约 + 本项目版本适配 |

## 视觉审查的五个问题

1. 用户能否在一眼内定位当前对象和下一步？
2. 减去一个边框、一个色块或一层卡片后，结构是否反而更清楚？
3. 当前密度是否适合真实语言与输入方式，而不只是适合英文截图？
4. 静态、选中、聚焦和错误是否仍属于同一视觉系统？
5. 去掉光效、过渡和产品大图后，页面的信息结构是否仍然成立？

## Definition of Done

**视觉与系统：**

- [ ] 已选定场景、密度和主题支持范围；没有默认把所有页面变成密集后台。
- [ ] 共享语义 token 是唯一可信来源；组件没有散落的业务无关 hex。
- [ ] 品牌色、系统反馈色、工作流状态色与图表色职责分明。
- [ ] 主次操作明确；没有为符合"一个载体"隐藏焦点或状态。
- [ ] 普通面板默认无外阴影；边框与圆角按角色一致。
- [ ] 中英文混排、数字、长标题与长导航名称不破坏对齐。

**交互与可访问性：**

- [ ] Default / hover / pressed / selected / focus / disabled / pending / error 已覆盖适用项。
- [ ] 文字对比度在真实合成底色上验证，包括 placeholder、错误、按钮 hover。
- [ ] 必要控件边界与图形状态符合非文本对比度要求。
- [ ] 键盘能完成主要流程，焦点不丢、不被遮挡；对话框关闭后合理归还焦点。
- [ ] 字符快捷键如有实现，可关闭/重映射或限焦点生效；输入法不误触。
- [ ] 触控不依赖 hover/右键；目标尺寸和间距合格，热区不重叠。
- [ ] 200% 缩放和等效 320px 重排验证；必要二维区域局部滚动。
- [ ] 减少动效模式与高对比/forced colors 环境仍可操作。
- [ ] 慢请求、失败、无权限和空结果区别清楚；用户输入不丢失。
- [ ] 乐观更新有正确恢复逻辑；高风险操作不伪装已成功。

**回归与交付：**

- [ ] 至少覆盖窄屏、常规桌面与宽屏；短视口、软键盘按目标平台验证。
- [ ] 如支持双主题，组件和浮层的全部关键状态都在两种主题下检查。
- [ ] 使用真实内容完成视觉走查，不只用短英文与理想数据。
- [ ] 对关键交互保留自动化或可重复的人工回归步骤。
- [ ] 记录基线截图、批准的例外及理由；例外没有扩散为第二套系统。
- [ ] 没有不当使用 Linear 品牌资产，也没有把本规范称为 Linear 官方标准。

## 用于审查报告的输出结构

审查现有界面时，按这个结构汇报，而不是逐条念检查表：

```
# [页面/组件名] Linear Style 审查

## 结论
一两句话：整体是否符合，最大的问题是什么

## 发现的问题（按严重度排列）
1. [问题] — 位置 — 对应规则（引用 color.md / typography.md 等具体条目）— 建议修法
2. ...

## 符合规范之处（可选，简短）

## 不构成问题的地方（可选）
说明哪些看似"不像 Linear"但实际属于规范允许的场景变化，避免过度修改
```
