# 交互、动效与反馈

## 动效时间表

| 场景 | 默认 | 变化范围 |
|---|---:|---|
| Hover / 颜色反馈 | 100ms | 高频状态可立即变化 |
| 菜单 / 小弹层进入 | 160ms | 高频命令菜单允许 0ms |
| 对话框 / 抽屉进入 | 200ms | 不以动画完成作为可交互条件 |
| 关闭 | 100ms | 通常不慢于进入 |
| 视图局部切换 | 160ms | 简单数据切换可 0ms |
| 营销一次性展示 | ≤300ms 为启动建议 | 必须服务内容，不做每段同款滚动入场 |

- 默认缓动 `cubic-bezier(.25,.46,.45,.94)`（`assets/linear-tokens.css` 的 `--ls-ease-out`）；这是选定曲线，不是唯一官方曲线。
- 颜色、背景、边框可以短过渡；空间变化优先 transform 与 opacity。
- 对话框可 opacity + `scale(.98 → 1)`；菜单可轻移 2–4px；不弹跳、不强加回弹。
- 不用 `transition: all`，避免布局、颜色、尺寸意外同时动画。
- 不把元素正常 hover 做成缩放卡片；平台触觉、拖拽和直接手势是另一类反馈。
- 跟手交互应可中断、可反向；弹簧参数取决于平台与实现，不能给一个跨框架 stiffness 数字当通用规范。
- 动画不阻塞键盘操作；不为给观众看清过渡而人为延迟响应。
- `prefers-reduced-motion` 下移除非必要空间动效、脉冲与自动播放装饰；保留即时状态反馈。

## 加载和网络反馈

| 情况 | 默认反馈 |
|---|---|
| 本地操作、已有数据 | 立即显示新状态 |
| 短请求 | 按钮/局部忙碌状态，避免 skeleton 闪一下 |
| 持续约 200ms 以上且确实缺内容 | 显示稳定骨架或局部进度 |
| 较长任务 | 说明正在做什么；能测量则给真实进度；适当提供取消 |
| 已有列表刷新 | 保留旧内容并标记刷新，不整页清空 |
| 请求失败 | 原位错误与重试；需要时辅以通知，不吞掉上下文 |

- 不禁止 spinner：小型内联 spinner 适合不确定短任务；避免无解释的整页 spinner。
- Skeleton 不是越多越好，不能替代真实空状态、权限错误或失败状态。
- 请求返回后不强制将 skeleton 多显示几百毫秒以"显得流畅"。
- 内容占位尺寸、图片比例、按钮宽度稳定，减少加载跳动。

## 乐观更新的边界

**适合：** 可撤销且低风险的收藏、轻量状态切换、列表排序等，前提是能正确处理失败。

**不应直接视为已成功：** 支付、永久删除、权限和共享范围调整、发布不可回退内容、涉及安全验证的状态。

启用乐观更新时必须：

1. 区分本地 pending 与服务器已确认状态。
2. 失败保留/恢复正确状态并提供重试或撤销。
3. 旧请求的失败不能回滚覆盖用户随后已成功的新操作。
4. 不重复产生副作用，不绕过鉴权、服务端校验或审计。
5. 读屏用户也能获知关键结果，而不是只有颜色瞬间变动。

## 键盘与快捷键

- 所有可操作功能都有常规键盘路径；快捷键不是 Tab 导航的替代品。
- 不强制每个动作配置快捷键；为高频动作提供少量一致、可发现的加速器。
- 不拦截浏览器/宿主必要快捷键，除非该产品环境明确支持且有等价路径。
- 编辑状态、`contenteditable`、组合输入和输入法候选期间不触发字符快捷键。
- **仅避开输入框还不够：** 单字母与字符序列快捷键必须能关闭、能重映射，或只在相应组件获得焦点时生效（WCAG 2.1.4）。
- `?` 也是字符快捷键，不因为需要 Shift 就自动获得豁免。
- Esc 由最上层处理，先关闭子菜单/弹层，不能一键把整个工作流退出。
- 菜单与列表采用符合其语义的方向键策略；普通页面不把方向键全部全局劫持。
- Tooltip 或菜单可展示快捷键；用户不需要记住快捷键才能找到功能。

## 文案与恢复

- 一件事在按钮、确认框、通知和历史记录里使用一致名称。
- 错误说清"什么没完成、是否保留、下一步怎么做"，不只说"出错了"。
- 避免对系统错误卖萌或归咎用户；避免用技术实现术语代替用户任务名。
- 危险动作写清对象和结果；撤销有效时尽量提供，但不要用假撤销替代不可逆确认。
- 空状态中的行动必须与原因匹配：无搜索结果给清除筛选，不总是给"创建项目"。

# 可访问性与跨平台要求

本节列出实施的关键基线，不等于声称覆盖 WCAG 2.2 全部成功准则。完整合规仍需结合真实产品审计。

## 对比度与颜色

- 正常文字至少 4.5:1；大号文字可按标准用 3:1，但小型 UI 一律按普通文字验证（WCAG 1.4.3）。
- Placeholder、辅助文字、未选中导航和 tooltip 同样受文字对比度要求约束。
- 必要非文本图形、状态与控件识别线索至少 3:1；装饰分隔线不机械套用此要求（WCAG 1.4.11）。
- 禁用内容允许弱化，但仍应让用户理解为何不可操作；正常信息不得借禁用名义降对比。
- 用合成后的最终颜色，测试 default、hover、pressed、selected、focus 与错误底。
- 正文链接默认下划线；不只用"跟正文差一点的蓝色"说明可点击。
- 状态和选择不只靠色相；用文本、形状、check、位置或其他线索。

**必须纠正的常见误区：**

1. **14px/510 不属于 WCAG 大号粗体文字。** 大号文字通常是至少 18pt（24 CSS px），或至少 14pt（约 18.67 CSS px）的粗体；510 不应自动当作 bold。
2. **Placeholder 也是文字**，不能因为它叫占位符就免除正常文字的对比度要求。
3. **元数据、时间戳、非当前导航都不是"禁用"或"装饰"。** 只要需要阅读，就必须按信息文字处理。
4. **44×44px 不是 WCAG 2.2 AA 对所有目标的统一最低值。** AA 2.5.8 是 24×24 CSS px 或符合其间距等例外；44px 是触控默认值，也对应更高目标尺寸要求的常见基线。
5. **"200% 缩放无滚动"不等于完成 Reflow 验收。** 还要检查等效 320 CSS px 宽度；必要二维表格等存在局部例外。

## 焦点与语义

- 所有可交互元素必须有可见焦点；默认 2px 实色 outline、2px offset。
- 焦点不被 sticky 顶栏、模态、底部操作条完全遮住；不被容器裁切。
- 选择、当前位置、键盘活动项和焦点是不同概念，不能用同一个模糊紫光混写。
- 优先使用平台原生语义；自定义控件必须完整实现名称、角色、状态与键盘行为。
- 图标按钮有可访问名称；重复名称加入对象上下文，如"移除成员 Alex"。
- 反馈通知使用适当 live region；不把每次 hover、每个骨架块都读出来。
- 模态管理背景不可交互和焦点归还；只写 `aria-modal` 不会自动实现这些行为。

## 尺寸、缩放与触控

- Web 指针目标按 WCAG 2.2 AA 24×24px 或其具体例外检查，不仅检查截图里的视觉尺寸。
- 触控默认 ≥44×44px；原生平台按其 pt/dp 与平台规范采用至少同等可用性。
- 200% 字体/页面缩放不丢内容、不遮挡操作；另验等效 320 CSS px 的重排。
- 二维数据表、地图、时间轴等必要二维区域可有局部滚动，普通正文和工具栏仍须重排。
- 不禁用用户缩放；不以放大后自动减小字号抵消用户意图。
- 文本间距覆盖、较大系统字体、本地化长文案下不裁切内容。
- 按钮的最小高度不替代垂直 padding 和可增长布局。

## 运动、高对比与平台

- 尊重减少动态效果偏好；自动动画不得妨碍阅读与操作。
- 支持系统高对比/forced colors 时，不覆盖系统颜色让焦点和勾选状态消失。
- 不使用"抗锯齿开关"作为跨平台字重一致性的保证；在目标系统实测字体。
- 非 Web 平台保留自己的控件语义、返回手势、焦点、输入法和系统辅助功能。
- 不将 CSS px 直接视为所有平台的物理像素；按逻辑单位映射并实测。
