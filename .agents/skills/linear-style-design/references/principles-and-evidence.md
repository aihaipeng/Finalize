# 设计哲学与判断方法

## 让内容获得注意力，让外壳提供方向

Linear 官方原则："Don't compete for attention you haven't earned."

- 内容区承载任务的主要对比；导航提供定位，不成为持续发光的广告位。
- 将当前页面、焦点、选中对象、执行结果表达清楚，而不是让所有元素等亮。
- 保留完成任务需要的上下文；减噪不是把有用信息藏进三层菜单。
- 同一操作区域默认一个主要操作；不必要时允许没有主要操作。

**判断方法：** 缩小截图，先看到的应是当前工作对象或主信息，而不是侧栏品牌块、十个彩色徽章和一排高亮按钮。

## 结构应该被感受到，而不是被画满

Linear 官方原则："Structure should be felt not seen."

- 先用对齐和间距分组，再决定是否增加分隔线。
- 相邻信息共享上下文时优先用行与分组，不默认给每段信息一个卡片容器。
- 线条必须解释关系：区域边界、表头、列对齐、拖放位置；不只为了"高级感"。
- 不把"每张卡都没有阴影"误当作"必须满屏卡片"。

## 精确但不僵硬

- 相同语义使用相同 token、尺寸与交互。
- 光学对齐高于对数字的迷信：图标不对称、字形侧边距和不同语言都可能需要 1–2px 调整。
- 默认字重、默认圆角、默认过渡要少；不要把每个采样值都升级为一个全局 token。
- 不因一处例外立即创建一整套变体系统；先判断例外是否真实、是否重复出现。

## 密度服务效率，不服务"看起来专业"

- 显示用户需要比较的信息，而不是堆积所有可取到的字段。
- 桌面列表可以紧凑；阅读、设置和移动交互必须给文字与输入留空间。
- 重要标题允许换行；错误和帮助文字不能被固定行高裁掉。
- 一个区域内密度一致；侧栏与设置表单可以采用不同密度。

## 快意味着反馈、连续性和可恢复

- 输入与本地交互立即响应，不用动画遮掩阻塞。
- 操作过程中保留用户上下文，避免整页闪烁、回顶、重新排序或焦点丢失。
- 网络失败要有明确结果和恢复路径，不以一条转瞬即逝的 toast 代替所有错误处理。
- 可安全撤销的高频操作适合乐观更新；付款、权限变更、永久删除等不能为了速度伪装成功。

## 约束品牌表达，而不是抹去品牌

- 一个品牌强调色可以有不同明度状态，它们仍属于同一色族。
- 数据图表、状态、头像、用户内容不计入"只能有一种颜色"的误读。
- 可以替换品牌色、语言字体和产品特有布局；保留秩序与克制即可。
- 不复制 Linear 的 Logo、wordmark、专有图形来建立自己的品牌身份。

## 三类场景，不能混为一谈

| 场景 | 首要目的 | 应继承 | 不应机械照搬 |
|---|---|---|---|
| 工作型产品 UI | 持续、高频、准确完成任务 | 紧凑布局、弱化外壳、稳定列表、键盘效率 | 营销大字、环境光、长入场动画 |
| 营销 / 品牌页面 | 解释价值、展示产品、引导行动 | 排版纪律、真实产品画面、克制色彩 | 28px 行和 13px 密集正文 |
| 文档 / 设置 / 移动阅读 | 理解信息、准确输入 | 清晰结构、语义颜色、可读正文 | 为"像 Linear"压缩文字和触控目标 |

**架构无关不等于场景无关。** 同一套原则可以适配不同前端，不能要求所有前端长成同一张桌面项目管理截图。

# 证据性质说明

这份规范不是 Linear 官方设计系统，而是综合多份调研、重新核对官方资料、公开页面实测与 WCAG 算术验证后制定的 Linear-inspired 实施基线。使用时请注意证据标签的边界：

| 标签 | 含义 | 使用边界 |
|---|---|---|
| **官方** | Linear 官方文章、品牌说明、产品文档明确表达 | 证明其写明的事实，不自动证明未公开的具体参数 |
| **实测** | 对公开页面 DOM、computed styles、字体与变量的读取；或对本机已安装正版客户端安装包内随包分发文件的直接读取 | 只代表指定页面/安装包版本和采样时刻，不等于登录后的完整应用，也不等于未来版本 |
| **验证** | 依照 W3C 规则重新计算或核对 | 用于纠正算术、标准解释和实施错误 |
| **规范** | 为统一实施而选定的参数、配方和工程要求 | 是本规范的决定，不冒充官方 token |

本参考中除明确标注"官方"/"实测"的事实说明外，所有 token 表、组件尺寸、断点和 CSS 示例都属于"规范"类——它们是经过归一化的实施基线，不是"Linear 全产品始终如此"的宣称。

**已知的真实歧义点（不要被单一来源误导）：**

- 主按钮默认反色还是用品牌靛蓝：两者在 Linear 真实产品中都存在（工作型 UI 反色、登录/品牌流程靛蓝），本规范按场景区分，不是二选一。
- `accent.fill` 的 hover 色不能直接用更亮的 `#828fff`：白字在该色上只有约 2.87:1 对比度，不达标。
- 暗色不是 Linear 风格的必要条件；产品同时支持浅色主题，浅色不是"次等主题"。
- Mono 字体不限定于代码场景，少量品牌强调标题（如错误页）也会使用，但不应成为正文标题的默认选择。
- 按钮圆角不是全局胶囊（pill）：系统级功能按钮常用 5–8px 矩形圆角，pill 更多用于营销 CTA、登录流程和紧凑控件。

完整的来源列表（官方文章 URL、页面实测记录、WCAG 对比度重算过程、桌面客户端逆向发现）保存在项目根目录的 `LINEAR_STYLE_DESIGN_GUIDELINES.md` 第 14 章，需要追溯具体证据时可查阅该文件。
