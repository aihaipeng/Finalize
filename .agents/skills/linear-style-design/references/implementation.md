# 架构无关的实施契约

## 三层足够

```text
设计决策：颜色角色、字阶、密度、状态规则
    ↓
共享语义 token：bg.surface / text.muted / focus.ring / action.primary.bg
    ↓
平台与组件实现：现有 CSS、主题对象、原生资源或设计工具变量
```

- 颜色、文字、边界与动作状态通过语义 token 消费。
- 组件配方组合 token 与交互行为；无需为每条 CSS 声明再创建一个 token。
- 不要求换框架、换组件库、接入主题引擎或添加状态管理依赖。
- 有成熟组件行为就复用，只调整必要的视觉与 token，不为外观重写可访问性基础。
- CSS 示例不是前端架构；任何架构都可以用相同语义实现。

## 各类前端的映射

| 环境 | 落地方式 | 不应发生 |
|---|---|---|
| 原生 HTML / 多页 / 服务端模板 | 共享样式文件 + 根主题属性 | 为 token 引入不必要构建链 |
| 任意组件型 Web 框架 | 根级语义变量 + 现有组件实现 | 每个组件各自定义深浅 hex |
| Utility CSS | 将语义名称映射到共享变量；按所用版本配置 | 复制某个版本配置后宣称所有版本通用 |
| CSS-in-JS / CSS Modules | 引用同一语义变量或现有主题对象 | 保持两套各自演化的颜色值 |
| SSR / 流式渲染 / 静态站 | 尽早解析主题，输出一致首屏；保持客户端状态一致 | 首屏闪白、hydration 主题不一致 |
| 桌面 Web 容器 | 相同 token；处理原生窗口安全区域与快捷键 | 伪造窗口控件、覆盖系统键盘行为 |
| 原生移动 / 桌面 | 将角色映射到原生主题、字体和形状资源 | 逐行翻译 CSS、使用未经核验的平台 API 名称 |
| 设计工具 | 相同语义名、主题模式、密度与组件状态 | 设计稿与实现各自手抄另一套色板 |

不提供绑定具体框架版本的 API 或 CLI 代码，以免把跨架构规范变成会过期的配置教程；真正实施时以项目当前版本和目标平台文档核对。

## 唯一可信来源与主题边界

- 一个项目只选一个可维护的 token 源；不要同时手动维护 CSS、JSON、设计工具三份权威值。
- 小项目可直接以 CSS 或现有主题文件为源（见 `assets/linear-tokens.css`）；多端项目再按需要导出平台资源。
- 如需 JSON，保存语义、值、类型和单位；颜色/尺寸不能脱离平台单位随意解释。
- 主题作用域必须覆盖门户浮层、tooltip、toast 和根层对话框；不只覆盖局部页面节点。
- 用户输入、权限、请求逻辑不属于皮肤层；换主题不得重置数据状态。
- 数据色与业务状态色独立映射；更换品牌不应让历史数据状态换语义。

## 最小实施顺序

1. **选场景与密度：** 工作型 UI、营销、阅读；明确主题支持范围。
2. **落 token：** 表面、文字、边界、动作、反馈、字体、间距与动效（复制 `assets/linear-tokens.css` 作为起点）。
3. **完成基础组件：** 按钮、输入、选择、导航、列表，含完整状态（参考 `components.md`）。
4. **完成浮层：** 菜单与对话框的焦点、位置、滚动、遮罩；有需求再做命令菜单。
5. **套入真实内容：** 中文、长名称、空数据、无权限、慢请求、失败和危险操作。
6. **校准视觉：** 灰阶、对齐、圆角和密度；最后才考虑装饰。
7. **验证：** 暗/亮、键盘、触控、缩放、对比度、减少动效与关键流程回归（参考 `review-checklist.md`）。

## CSS 参考 token 使用约定

`assets/linear-tokens.css` 是与本规范默认值一致的 Web 参考，不包含字体文件、组件库或主题选择器功能：

- 无显式主题时跟随系统；无系统深色偏好时回退浅色。
- 显式主题只在 `html` 上设置 `data-theme="light"` 或 `data-theme="dark"`，不实现局部嵌套主题。
- 页面声明正确的 `lang`；中文 UI 使用 14px 档；CJK 字距不要套拉丁负值。
- 只定义 token 与几个标注过的基础配方，不注入全局 reset，不重写默认 `body/h1/button` 样式。
- 默认系统等宽字体足够；Inter 需要项目自行合法加载，加载失败会使用回退字体。
- 原生端使用相同语义角色，不必实现 CSS。

**没有塞进这份 CSS 的内容**（需要项目自己补）：

- 没有模拟全套按钮、菜单、dialog 行为；外观 CSS 不等于完整组件。
- 没有全局把所有动画设成 `0.01ms !important`；项目应通过动效 token 和显式偏好处理，不破坏依赖生命周期事件的现有逻辑。
- 没有全局 OpenType、抗锯齿、`outline: none`、`font-variation-settings` 强制覆盖。
- 没有把固定 `height` 强加给所有控件；内容、字号与错误说明可以自然增长。
- 没有定义业务状态和图表色；它们需要真实领域模型，不能从 Linear issue 状态照搬。
- 没有为少量变量要求安装库或主题生成器。

代码为了无构建、保守兼容，在系统深色分支重复了同一组深色角色值。实际项目若已有 token 生成工具，应从一个源生成，不能让两份值独立演化。
